# 每周杂事（WeeklyTrifles）任务详解

## 1. 文件概述

每周杂事任务是《阴阳师》手游中每周需要完成的分享和召唤类杂项任务的自动化脚本模块。这些任务每周重置，完成后可获得勾玉等奖励。

**核心功能：**
- **图鉴分享**：进入式神图鉴 → 分享到微信 → 领取勾玉奖励
- **地鬼分享**：进入地域鬼王 → 选择已挑战的鬼王 → 分享到微信 → 领取勾玉
- **秘闻分享**：进入秘闻副本 → 分享到微信 → 领取勾玉
- **破碎符咒召唤**：自动消耗破碎符咒进行召唤（支持 10 次/50 次切换）

**文件组成：**
| 文件 | 作用 |
|------|------|
| `script_task.py` | 任务主逻辑，含四个子任务 |
| `config.py` | 配置模型定义（调度器、分享开关、召唤数量） |
| `assets.py` | 图像/点击/OCR 资源定义（自动生成） |

## 2. 配置参数说明

### 2.1 Scheduler（调度器）

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `success_interval` | `TimeDelta` | `7天` | 成功后的下次调度间隔 |
| `failure_interval` | `TimeDelta` | `7天` | 失败后的下次调度间隔 |

### 2.2 Trifles（杂事配置）

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `share_collect` | `bool` | `True` | 是否执行图鉴分享 |
| `share_area_boss` | `bool` | `True` | 是否执行地鬼分享 |
| `share_secret` | `bool` | `True` | 是否执行秘闻分享 |
| `broken_amulet` | `int` | `100` | 破碎符咒召唤目标次数（0 表示不执行） |

## 4. 核心代码逐行解释

### 4.1 `run()` 主方法

```python
def run(self):
    con = self.config.weekly_trifles.trifles
    if con.share_collect:
        self._share_collect()
    if con.share_area_boss:
        self._share_area_boss()
    if con.share_secret:
        self._share_secret()
    if con.broken_amulet:
        self._broken_amulet(con.broken_amulet)
    self.set_next_run(task='WeeklyTrifles', success=True, finish=True)
    raise TaskEnd('WeeklyTrifles')
```
- 按配置依次执行四个子任务
- 所有子任务执行完后设置 7 天后再次运行

def _share_secret(self):
    self.ui_goto(page_secret_zones)
    valid = False
    while 1:
        self.screenshot()
        if self.appear(self.I_WT_SE_WECHAT):
            self.wait_until_stable(self.I_WT_SE_WECHAT, skip_first_screenshot=True)
            break
        if self.appear_then_click(self.I_WT_ENTER_SE, interval=1):
            continue
        if self.appear_then_click(self.I_WT_SE_SHARE, interval=5):

## 5. 任务执行流程图

```
开始
  │
  ▼
[图鉴分享] share_collect=True?
  ├── 否 → 跳过
  └── 是 ↓
  导航到图鉴 → 点击式神 → 点击分享
  → 点击微信分享 → 模拟分享 → 领取奖励 → 返回
  │
  ▼
[地鬼分享] share_area_boss=True?
  ├── 否 → 跳过
  └── 是 ↓
  导航到地鬼页面
  ├── 今天没打过 → 退出
  └── 已打过 → 选择鬼王 → 分享 → 领取奖励 → 返回
  │
  ▼
[秘闻分享] share_secret=True?
  ├── 否 → 跳过
  └── 是 ↓
  导航到秘闻页面
  ├── 本周没打过 → 退出
  └── 已打过 → 分享 → 领取奖励 → 返回
  │
  ▼
[破碎符咒] broken_amulet > 0?
  ├── 否 → 跳过
  └── 是 ↓
  导航到召唤页面
  → 检查符咒数量
  → 循环召唤（10次/50次智能切换）
  → 达到目标或符咒用完 → 退出
  │
  ▼
设置下次运行（7天后）→ TaskEnd
```

## 6. 设计模式总结

### 6.1 任务编排模式
- `run()` 方法作为编排器，按配置条件依次调用子任务
- 每个子任务独立封装为 `_share_*()` 或 `_broken_amulet()` 方法
- 子任务之间无依赖，可独立启用/禁用

### 6.2 通用分享模板
- `click_share()` 方法抽象了分享的通用流程：
  1. 点击分享按钮 → 等待二维码
  2. 点击二维码区域 → 等待奖励
  3. 超时处理
- 不同分享场景（地鬼/秘闻）复用同一模板

### 6.3 已领取检测模式
- 每个分享任务都通过检查勾玉标识判断是否已领取
- `I_WT_AB_JADE` / `I_WT_SE_JADE` 不存在 → 已领取
- 避免重复分享浪费时间

### 6.4 智能批量召唤
- 通过 OCR 识别"10次"和"50次"按钮位置
- 通过图像匹配判断当前选中状态
- 动态切换策略：
  - 剩余 >= 50：使用 50 次加速
  - 剩余 < 50：切回 10 次精确控制
- `random_click()` 模拟随机点击跳过召唤动画

### 6.5 嵌套退出模式
- `_broken_amulet()` 使用嵌套的 `exit_amulet()` 内部函数
- 统一的退出逻辑：等待确认按钮 → 点击消失
- 在多个退出点复用（超时、符咒用完、正常结束）

### 6.6 定时器防死循环
- `Timer` 类在多个地方防止死循环：
  - `click_share()`：7 秒超时
  - 图鉴分享：3 秒超时
  - 召唤动画：5 秒超时
- 超时后优雅退出，不抛异常
