# 爬塔活动（ActivityShikigami）详解

## 1. 文件概述

爬塔活动是阴阳师限时活动中的核心玩法模块，支持多种爬塔模式（门票爬塔、体力爬塔、Boss爬塔、100体爬塔）。该任务自动完成从庭院导航到活动页面、切换御魂、锁定/解锁阵容、检测门票数量、发起战斗、处理战斗结果的全流程自动化。

**涉及文件：**
- `script_task.py` — 任务主逻辑，包含状态机、战斗循环、御魂切换等
- `config.py` — 配置定义，包含御魂切换配置、战斗配置、调度器配置
- `assets.py` — 资源定义，包含图片匹配规则、点击区域、OCR识别区域
- `page.py` — 页面导航定义，描述活动页面之间的跳转关系

### 4.1 图像预处理函数 `_prepare_image_for_ocr`

```python
def _prepare_image_for_ocr(image: np.ndarray, asset: RuleOcr) -> np.ndarray:
```
该函数用于对截图中的特定ROI区域进行图像预处理，以提高OCR识别准确率。

```python
    image_copy = image.copy()                          # 复制原图，避免修改原始数据
    x, y, w, h = asset.roi                             # 获取OCR资源的ROI坐标和尺寸
    roi_to_process = image_copy[y:y + h, x:x + w]     # 裁剪出ROI区域
```
从截图中裁剪出需要处理的区域。

```python
    if len(roi_to_process.shape) == 3:
        gray_image = cv2.cvtColor(roi_to_process, cv2.COLOR_BGR2GRAY)  # 彩色图转灰度
    else:
        gray_image = roi_to_process                     # 已经是灰度图则直接使用
```
将图像转换为灰度图，便于后续二值化处理。

```python
    _, binary_norm = cv2.threshold(gray_image, 127, 255, cv2.THRESH_BINARY | cv2.THRESH_OTSU)
    _, binary_inv = cv2.threshold(gray_image, 127, 255, cv2.THRESH_BINARY_INV | cv2.THRESH_OTSU)
```
使用OTSU自适应阈值进行二值化，同时生成正向和反向二值图。

```python
    if cv2.countNonZero(binary_norm) < cv2.countNonZero(binary_inv):
        binary_correct = binary_norm                   # 正向二值图白色像素少，说明背景是白色
    else:
        binary_correct = binary_inv                    # 反向二值图白色像素少，说明背景是黑色
```
自动判断哪个二值化结果是正确的（文字为白色，背景为黑色）。

```python
    kernel = cv2.getStructuringElement(cv2.MORPH_RECT, (5, 1))
    dilated_image = cv2.dilate(binary_correct, kernel, iterations=1)
```
使用5x1的矩形核进行膨胀操作，连接断裂的文字笔画。

```python
    contours, _ = cv2.findContours(dilated_image, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
```
查找轮廓，用于定位文字区域。

```python
    if contours:
        all_points = np.concatenate(contours, axis=0)   # 合并所有轮廓点
        bx, by, bw, bh = cv2.boundingRect(all_points)   # 计算整体边界框
        processed_roi_content = binary_correct[by:by + bh, bx:bx + bw]  # 裁剪出文字区域
```
将所有轮廓合并，计算包围所有文字的最小矩形。

```python
    centered_roi = np.full((h, w), 255, dtype=np.uint8)  # 创建白色背景
    if processed_roi_content is not None:
        content_h, content_w = processed_roi_content.shape
        if content_h <= h and content_w <= w:
            start_y = (h - content_h) // 2               # 计算居中位置
            start_x = (w - content_w) // 2
            paste_area = centered_roi[start_y:start_y + content_h, start_x:start_x + content_w]
            paste_area[processed_roi_content == 255] = 0  # 将白色文字区域设为黑色
```
将提取的文字居中放置在白色画布上，提高OCR识别率。

```python

            self._count_map = {climb_type: 0 for climb_type in self.conf.general_climb.run_sequence_v}
        return self._count_map
```
延迟初始化运行次数映射表。

```python
    def put_status(self):
        def get_count(self) -> int:
            return self.count_map[self.climb_type]       # 获取当前类型已运行次数
        def get_limit(self) -> int:
            limit = getattr(self.conf.general_climb, f'{self.climb_type}_limit', 0)
            return 0 if not limit else limit             # 获取当前类型的次数限制

        if self.limit_time is not None and datetime.now() - self.start_time >= self.limit_time:
            raise LimitTimeOut                           # 超时则抛出超时异常
        if get_count(self) >= get_limit(self):
            raise LimitCountOut                          # 达到次数限制则抛出次数异常
```
状态检查函数，每次循环调用，检查是否需要停止当前爬塔类型。

### 4.3 主任务类 `ScriptTask`

```python
class ScriptTask(StateMachine, GameUi, BaseActivity, SwitchSoul, ActivityShikigamiAssets):
```
多重继承：状态机 + 游戏UI操作 + 基础活动 + 御魂切换 + 资源定义。

```python
    def run(self) -> None:
        self.limit_time: timedelta = self.conf.general_climb.limit_time_v  # 设置总运行时间限制

        for climb_type in self.conf.general_climb.run_sequence_v:          # 遍历运行序列
            self.ui_get_current_page()                   # 检测当前页面
            self.ui_goto(game.page_climb_act)            # 导航到爬塔活动页面
            try:
                method_func = getattr(self, f'_run_{climb_type}')  # 动态获取对应爬塔方法
                method_func()                            # 执行爬塔
            except LimitCountOut as e:
                self.ui_click(self.I_UI_BACK_YELLOW, stop=self.I_TO_BATTLE_MAIN, interval=1)  # 次数用完，返回
            except LimitTimeOut as e:
                break                                    # 超时，退出循环
            finally:
                self.switch_next()                       # 无论成功失败都切换下一个

        logger.hr("Exit Shikigami", 2)
        self.ui_get_current_page(False)
        self.ui_goto(game.page_main)                     # 返回庭院
        if self.conf.general_climb.active_souls_clean:
            self.set_next_run(task='SoulsTidy', ...)     # 如果配置了，触发御魂清理任务
        self.set_next_run(task="ActivityShikigami", success=True)  # 设置下次执行时间
        raise TaskEnd                                    # 抛出任务结束异常
```
主运行流程：遍历爬塔序列 → 导航 → 动态调用 → 异常处理 → 返回庭院。

### 4.4 门票爬塔 `_run_pass`

```python
    def _run_pass(self):
        self.ui_clicks([self.I_TO_BATTLE_MAIN, self.I_TO_BATTLE_MAIN_2],
                       stop=self.I_CHECK_BATTLE_MAIN, interval=1)  # 点击进入战斗主界面
        self.switch_soul(self.I_BATTLE_MAIN_TO_RECORDS, self.I_CHECK_BATTLE_MAIN)  # 切换御魂
        self.switch_climb_mode_in_game('pass')           # 切换到门票模式

        ocr_limit_timer = Timer(1).start()               # OCR检测频率限制（每秒一次）
        click_limit_timer = Timer(4).start()             # 点击频率限制
        while 1:
            self.screenshot()                            # 截图
            self.put_status()                            # 检查状态（超时/次数）
            if (self.appear_then_click(self.I_UI_CONFIRM, interval=0.5)
                    or self.appear_then_click(self.I_UI_CONFIRM_SAMLL, interval=0.5)):
                continue                                 # 处理确认弹窗
            if self.ui_reward_appear_click():
                continue                                 # 处理奖励弹窗
            if not ocr_limit_timer.reached():
                continue                                 # OCR检测频率限制
            ocr_limit_timer.reset()
            if not self.ocr_appear(self.O_FIRE):
                continue                                 # 未检测到"挑战"按钮，等待
            self.lock_team(self.conf.general_battle)     # 锁定/解锁阵容
            if not self.check_tickets_enough():
                break                                    # 门票不足，退出
            if self.conf.general_climb.random_sleep:
                random_sleep(probability=0.2)            # 随机休眠防检测
            if self.start_battle():
                continue                                 # 开始战斗

        self.ui_click(self.I_UI_BACK_YELLOW, stop=self.I_TO_BATTLE_MAIN, interval=1)  # 返回
```

```python

        while 1:
            sleep(random.uniform(0.5, 1.5))              # 随机等待0.5-1.5秒
            self.screenshot()
            if ok_cnt > max_retry:
                break                                    # 超过最大重试次数
            if ok_cnt > 0 and self.ocr_appear(self.O_FIRE):
                return True                              # 检测到"挑战"按钮，说明已退出战斗
            if self.appear(self.I_FALSE):
                self.ui_click_until_smt_disappear(...)   # 战斗失败，点击关闭
                return False
            if self.appear_then_click(self.I_WIN, interval=2):
                continue                                 # 战斗胜利，点击确认
            if self.appear(self.I_REWARD) or ...:        # 检测到奖励图标
                self.random_reward_click(...)
                ok_cnt += 1
                continue
            if ok_cnt > 3 and not self.is_in_battle(False):
                self.random_reward_click(...)            # 已不在战斗中，随机点击
                ok_cnt += 1
                continue
            if ok_cnt == 0 and random_click_swipt_enable:
                self.random_click_swipt()                # 战斗中随机滑动（防检测）
```
战斗等待的核心循环：通过图像识别判断战斗状态，处理胜利/失败/奖励等情况。

### 4.6 御魂切换 `switch_soul`

```python
    def switch_soul(self, enter_button: RuleImage, cur_img: RuleImage):
        conf = self.conf.switch_soul_config
        enable_switch = getattr(conf, f"enable_switch_{self.climb_type}", False)
        enable_by_name = getattr(conf, f"enable_switch_{self.climb_type}_by_name", False)
        if not enable_switch and not enable_by_name:
            return                                       # 未启用切换则跳过

        conf.validate_switch_soul()                      # 验证配置有效性
        self.ui_click(enter_button, stop=self.I_CHECK_RECORDS, interval=1)  # 进入式神录
        if enable_by_name:
            group, team = getattr(conf, f"{self.climb_type}_group_team_name").split(",")
            self.run_switch_soul_by_name(group, team)    # 通过名称切换御魂
        elif enable_switch:
            group_team = getattr(conf, f"{self.climb_type}_group_team")
            self.run_switch_soul(group_team)             # 通过编号切换御魂
        self.ui_click(self.I_UI_BACK_YELLOW, stop=cur_img, interval=1)  # 返回
```
支持两种御魂切换方式：按编号和按名称（OCR识别）。

## 6. 设计模式总结

### 6.1 状态机模式
`StateMachine`类实现了经典的状态机模式，通过`run_idx`管理当前状态（爬塔类型），通过`put_status()`进行状态检查，通过`switch_next()`进行状态转换。异常`LimitTimeOut`和`LimitCountOut`用于状态转换的触发。

### 6.2 策略模式
不同爬塔类型（pass/ap/boss/ap100）通过`getattr(self, f'_run_{climb_type}')`动态分发，实现了策略模式。每种爬塔类型有独立的运行方法，但共享相同的状态检查和战斗框架。

### 6.3 模板方法模式
`ScriptTask.run()`定义了任务执行的骨架流程（导航→执行→返回），具体的爬塔逻辑由子方法`_run_pass`、`_run_ap`等实现。

### 6.4 多重继承组合
`ScriptTask`通过多重继承组合了多个功能模块：
- `StateMachine` — 状态管理
- `GameUi` — UI导航操作
- `BaseActivity` — 基础活动功能
- `SwitchSoul` — 御魂切换功能
- `ActivityShikigamiAssets` — 资源定义

### 6.5 资源与逻辑分离
所有图片、点击区域、OCR区域都定义在`assets.py`中，通过类属性访问。资源由`dev_tools/assets_extract.py`自动生成，实现了资源定义与业务逻辑的完全分离。

### 6.6 页面导航图
`page.py`使用`Page`对象和`link()`方法定义页面之间的跳转关系，形成有向图结构，`GameUi.ui_goto()`自动寻路实现页面导航。
