# Utils 工具模块 逐行代码详解

## 1. 文件概述

`Utils` 模块提供了**工具类和枚举定义**：

- **config_enum.py**：游戏内枚举定义（式神等级、逢魔BOSS类型）
- **post_diagnotor.py**：异常后诊断器（检测御魂溢出等特定错误）
- **assets.py**：资源定义（空）

## 2. 配置参数说明

### ShikigamiClass 式神等级枚举

| 值 | 说明 |
|----|------|
| `UR` | UR 级式神 |
| `SP` | SP 级式神 |
| `SSR` | SSR 级式神 |
| `SR` | SR 级式神 |
| `R` | R 级式神 |
| `N` | N 级式神 |
| `MATERIAL` | 材料 |

### DemonClass 逢魔BOSS枚举

| 值 | 说明 |
|----|------|
| `TSUCHIGUMO` | 土蜘蛛 |
| `OBOROGURUMA` | 胧车 |
| `ODOKURO` | 荒骷髅 |
| `NAMAZU` | 地震鲇 |
| `SHINKIRO` | 蜃气楼 |
| `GHOSTLY_SONGSTRESS` | 鬼灵歌伎 |
| `BOSS_7` | 夜荒魂 |

### AnalyzeType 诊断类型枚举

| 值 | 说明 |
|----|------|
| `NONE` | 无异常 |
| `SoulOverflow` | 御魂溢出 |

## 3. 资源定义说明

`assets.py` 定义了空的 `UtilsAssets` 类。`PostDiagnotor` 通过继承 `GlobalGameAssets` 和 `SoulsTidyAssets` 获得所需资源。

## 4. 核心代码逐行解释

### 4.1 ShikigamiClass 枚举（config_enum.py 第6-14行）

```python
class ShikigamiClass(str, Enum):
    UR = 'UR'
    SP = 'SP'
    SSR = 'SSR'
    SR = 'SR'
    R = 'R'
    N = 'N'
    MATERIAL = 'MATERIAL'
```

- **第6-14行**：式神等级枚举。用于配置中指定式神筛选条件，如只保留 SSR 以上式神。

### 4.2 DemonClass 枚举（config_enum.py 第17-31行）

```python
class DemonClass(str, Enum):
    TSUCHIGUMO = '土蜘蛛'
    OBOROGURUMA = '胧车'
    ODOKURO = '荒骷髅'
    NAMAZU = '地震鲇'
    SHINKIRO = '蜃气楼'
    GHOSTLY_SONGSTRESS = '鬼灵歌伎'
    BOSS_7 = '夜荒魂'
```

- **第17-31行**：逢魔之时 BOSS 类型枚举。使用中文值，便于配置文件中直接使用中文名称。

### 4.3 PostDiagnotor 异常诊断器（post_diagnotor.py 第12-23行）

```python
class AnalyzeType(str, Enum):
    NONE = "none"
    SoulOverflow = "soul_overflow"

class PostDiagnotor(GlobalGameAssets, SoulsTidyAssets):
    def handle(self, e: Exception, command: str, image: np.ndarray) -> AnalyzeType:
        if self.I_ST_SOUL_OVERFLOW.match(image) and \
                (self.I_UI_CONFIRM_SAMLL.match(image) or self.I_UI_GOTIT_SMALL.match(image)):
            logger.warning(f"Detect soul overflow, command: {command}")
            return AnalyzeType.SoulOverflow
        return AnalyzeType.NONE
```

- **第12-23行**：异常后诊断器。当任务执行过程中发生异常时，通过图像匹配检测具体原因：
  - 检测 `I_ST_SOUL_OVERFLOW`（御魂溢出图标）+ `I_UI_CONFIRM_SAMLL`（确认按钮）→ 判定为御魂溢出
  - 其他情况返回 `NONE`

使用场景：任务执行异常后，调度器调用此诊断器判断是否为可自动处理的错误类型。

## 5. 任务执行流程图

```
Utils 工具模块
│
├── config_enum.py 枚举定义
│   ├── ShikigamiClass: UR/SP/SSR/SR/R/N/MATERIAL
│   └── DemonClass: 土蜘蛛/胧车/荒骷髅/...
│
└── post_diagnotor.py 异常诊断
    ├── 继承 GlobalGameAssets + SoulsTidyAssets
    └── handle()
        ├── 检测御魂溢出
        │   ├── I_ST_SOUL_OVERFLOW 匹配
        │   └── I_UI_CONFIRM_SAMLL 或 I_UI_GOTIT_SMALL 匹配
        ├── 匹配成功 → 返回 SoulOverflow
        └── 未匹配 → 返回 NONE
```

## 6. 设计模式总结

| 设计模式 | 应用位置 | 说明 |
|----------|----------|------|
| **枚举模式** | `ShikigamiClass`/`DemonClass` | 类型安全的常量定义 |
| **诊断器模式** | `PostDiagnotor` | 异常后自动检测错误类型 |
| **图像匹配** | `handle()` 方法 | 通过模板匹配判断屏幕状态 |
| **多重继承** | `PostDiagnotor` | 继承多个资源类获取所需图像资源 |
