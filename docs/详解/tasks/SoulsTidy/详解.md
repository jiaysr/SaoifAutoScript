# 御魂整理任务详解

## 1. 文件概述

御魂整理（SoulsTidy）是《阴阳师》游戏中的御魂管理功能。该自动化脚本实现了以下功能：

- 自动导航至式神录的御魂界面
- **贪吃鬼喂食**：自动喂食贪吃鬼，消耗多余的低级御魂
- **奉纳（招财猫）**：自动奉纳已弃置的+0御魂，获取金币奖励
- 自动处理御魂溢出提示、神赐奖励弹窗等

### 文件清单

| 文件 | 说明 |
|------|------|
| `script_task.py` | 任务主逻辑，包含贪吃鬼喂食和奉纳两个核心流程 |
| `config.py` | 配置定义，包含贪吃鬼和奉纳的启用开关 |
| `assets.py` | 资源定义，包含大量图片模板、OCR规则和长按操作 |

## 4. 核心代码逐行解释

### `ScriptTask` 类

```python
class ScriptTask(GameUi, SoulsTidyAssets):
```

继承 `GameUi`（页面导航）和 `SoulsTidyAssets`（资源定义）。

### `run()` 方法 — 主入口

```python
def run(self):
    self.ui_get_current_page()
    self.ui_goto(page_shikigami_records)
    con = self.config.souls_tidy
    if con.simple_tidy.enable_greed or con.simple_tidy.enable_maneki:
        self.goto_souls()
        self.greed_maneki()
        self.back_records()
    self.set_next_run(task='SoulsTidy', success=True, finish=False)
    raise TaskEnd('SoulsTidy')
```

**执行流程**：
1. 导航到式神录页面
2. 如果贪吃鬼或奉纳任一启用，进入御魂界面
3. 执行 `greed_maneki()` 处理贪吃鬼和奉纳
4. 返回式神录
5. 设置下次运行时间

### `goto_souls()` — 进入御魂主界面

```python
def goto_souls(self):
    while 1:
        self.screenshot()
        if self.appear(self.I_ST_GREED) and self.appear(self.I_ST_TIDY):
            break
        if self.appear_then_click(self.I_ST_REPLACE, interval=1):
            continue
        if self.appear_then_click(self.I_ST_SOULS, interval=1):
            continue
        if self.appear_then_click(self.I_ST_SOULS_CLOSE, interval=1):
            continue
        if self.click(self.C_ST_DETAIL, interval=2):
            continue
    self.ocr_appear_click(self.O_ST_OVERFLOW)
    logger.info('Enter souls page')
```

**进入逻辑**：
- 目标状态：贪吃鬼图标和整理图标同时出现
- 尝试依次点击：更换按钮 → 御魂标签 → 关闭状态的御魂标签 → 详细区域
- 进入后处理御魂溢出提示（点击"知道了"）

### `back_records()` — 返回式神录

```python
def back_records(self):
    self.ui_click(self.I_UI_BACK_YELLOW, self.I_CHECK_RECORDS)
```

点击黄色返回按钮，直到检测到式神录界面标志。

## 6. 设计模式总结

### 6.1 流水线模式

整个御魂整理流程呈线性流水线：贪吃鬼喂食 → 关闭 → 切换奉纳 → 排序 → 逐个奉纳。每个阶段有明确的入口条件和出口条件。

### 6.2 OCR辅助决策

大量使用OCR识别来辅助决策：
- 排序方式识别（`O_ST_SORT_*`）
- 金币数量验证（`O_ST_GOLD`）
- 御魂等级验证（`O_ST_FIRSET_LEVEL`）

OCR结果用于动态控制流程走向，而非硬编码坐标。

### 6.3 弹窗处理模式

采用统一的弹窗处理模式：在每个循环中检测并处理可能出现的弹窗（确认弹窗、未选中弹窗、神赐弹窗），确保流程不被意外弹窗阻塞。

### 6.4 重复操作的计数控制

贪吃鬼喂食使用 `feed_count` 计数器限制最多3次，奉纳循环通过OCR检测等级来判断终止条件，避免无限循环。

### 6.5 误识别容错

OCR将"+0"识别为"古"，代码中使用 `firvel != '古'` 作为判断条件，体现了对OCR误识别的容错处理。
