# 悬赏封印任务详解

## 1. 文件概述

悬赏封印（WantedQuests）是《阴阳师》游戏中的日常玩法。玩家需要击败指定怪物以完成悬赏任务，获取挑战券、金币等奖励。该自动化脚本实现了以下功能：

- 自动追踪悬赏封印任务
- 智能识别任务类型（挑战/秘闻/探索）并选择最优执行策略
- 自动执行战斗任务
- 协作任务邀请好友
- 支持换御魂、秘闻层数限制、不想打的BOSS过滤等高级功能

### 文件清单

| 文件 | 说明 |
|------|------|
| `script_task.py` | 任务主逻辑，包含任务识别、执行策略、协作邀请等 |
| `config.py` | 配置定义，包含协作类型、战斗优先级、层数限制等 |
| `assets.py` | 资源定义，包含大量图片模板和OCR规则 |
| `explore.py` | 探索战斗相关逻辑（`WQExplore`、`ExploreWantedBoss`） |

### 子目录

| 目录 | 说明 |
|------|------|
| `wq/` | 悬赏封印主界面资源 |
| `chanllenge/` | 挑战界面资源 |
| `invite/` | 邀请界面资源 |

## 2. 配置参数说明

### `WantedQuestsConfig` — 悬赏封印配置

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `before_end` | `Time` | `00:00:00` | 在每日重置前多久停止执行 |
| `invite_friend_name` | `str` | `""` | 协作任务邀请的好友名称（空则随机邀请） |
| `cooperation_type` | `CooperationSelectMaskDescription` | `Any` | 协作任务邀请类型筛选 |
| `battle_priority` | `str` | `挑战 > 秘闻 > 探索` | 战斗类型优先级 |
| `cooperation_only` | `bool` | `False` | 是否只完成协作任务 |
| `unwanted_boss_names` | `str` | `酒吞童子,阎魔` | 不想打的BOSS名称（逗号分隔） |
| `layer_limit` | `LayerLimit` | `柒` | 秘闻副本层数限制（该层及以上不打） |

### `CooperationType` — 协作类型枚举

| 值 | 名称 | 说明 |
|----|------|------|
| 1 | `Gold` | 金币协作 |
| 2 | `Jade` | 勾玉协作 |
| 4 | `Food` | 狗/猫粮协作 |
| 8 | `Sushi` | 体力协作 |

### `CooperationSelectMask` — 协作选择掩码

使用位掩码组合筛选协作类型：
- `NoInvite (0)`：不自动邀请
- `GoldOnly (1)`：仅金币协作
- `JadeOnly (2)`：仅勾玉协作
- `Any (15)`：所有协作都邀请

### `LayerLimit` — 秘闻层数限制

| 值 | 说明 |
|----|------|
| `壹` ~ `拾` | 第1~10层 |
| `番外` | 番外篇 |
| `无限制` | 所有层都打 |

### `WantedQuests` — 任务总配置

| 参数 | 类型 | 说明 |
|------|------|------|
| `scheduler` | `Scheduler` | 任务调度配置 |

### `find_wq()` — 任务识别

```python
def find_wq(self, img):
    res_list = self.O_WQ_TEXT_ALL.detect_and_ocr(img)
    reg_time = re.compile(r'^([01]?[0-9]|2[0-3]):([0-5]?[0-9]):?([0-5]?[0-9])?$')
    reg_fengyin = re.compile(r'.*[封|野]印.*')
    reg_progress = re.compile(r'^(\d+)([7/])(\d+)$')
    reg_XX = re.compile(r'^(\d+)\1$')
    reg_other = re.compile(r'[?？协边]')
```

使用多个正则表达式过滤OCR结果：
- `reg_time`：过滤时间格式
- `reg_fengyin`：识别"封印"文字
- `reg_progress`：识别进度格式（如"3/10"，注意"/"可能被误识别为"7"）
- `reg_XX`：过滤重复数字（如"1414"）
- `reg_other`：过滤无关字符

```python
    for index, res in enumerate(res_list):
        if reg_fengyin.match(res.ocr_text):
            continue
        if reg_time.match(res.ocr_text):
            continue
        # ...
        if (match := reg_progress.match(res.ocr_text)):
            spliter_index = match.start(2)
            xywh = calc_xywh(res.box)

            if cu > total:
                cu = cu // 10

```

**进度解析**：
- 解析"当前/总数"格式
- 总数超过14时取模（OCR误识别修正）
- 当前超过总数时整除10（OCR误识别修正）
- 当前等于总数表示已完成

## 6. 设计模式总结

### 6.1 策略模式

`name_funcs` 字典将任务类型映射到处理函数：
```python
name_funcs = {'式神': self.challenge, '探索': self.explore, '秘闻': self.secret}
```
通过策略模式实现不同类型任务的差异化处理。

### 6.2 位掩码筛选

协作类型使用位掩码（Gold=1, Jade=2, Food=4, Sushi=8），通过位运算实现灵活的组合筛选。

### 6.3 OCR容错处理

- "/"被误识别为"7"时的修正
- 总数超过14时取模修正
- 当前数超过总数时整除修正
- 多种正则过滤无关OCR结果

### 6.4 重试机制

- 协作邀请最多重试5次，每次间隔20秒
- 任务识别失败时上滑列表重试
- 错误计数超过3次时退出

### 6.5 动态资源区域

```python
self.O_WQ_TEXT_ALL.area = area
```

通过 `find_wq` 识别到的任务位置动态更新OCR资源的识别区域，提高后续识别精度。

### 6.6 亮度检测高亮状态

`appear_highlight` 方法通过计算区域平均亮度来判断按钮是否处于高亮状态，解决了传统模板匹配无法区分选中/未选中的问题。
