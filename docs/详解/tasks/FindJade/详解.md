# 找勾玉 (FindJade) 任务详解

## 1. 文件概述

找勾玉是《阴阳师》中通过**悬赏封印协作任务**获取勾玉的自动化方案。本任务实现了**多账号自动切换 + 协作任务邀请**功能，核心特点：

- **多小号管理**：支持配置多个小号，自动轮流登录执行悬赏封印
- **智能登录判断**：根据上次登录时间判断是否需要再次登录（避免重复操作）
- **动态模块加载**：运行时动态加载 `WantedQuests` 任务模块并注入扩展方法
- **协作邀请系统**：支持配置多个被邀请人，按类型和时间智能邀请
- **跨日夜处理**：正确处理18:00/5:00日夜交替的登录逻辑

### 文件清单

| 文件 | 用途 |
|------|------|
| `script_task.py` | 任务主入口，多账号循环和动态模块加载 |
| `config.py` | 配置参数定义（账号信息、邀请信息、序列化） |
| `assets.py` | 资源定义（空，复用 WantedQuests 的资源） |
| `WantedQuestsEx.py` | WantedQuests 任务的扩展方法（邀请VIP等） |

class InviteInfo(BaseModel):
    name: str = Field(default="")                                    # 被邀请人昵称
    default_invite_type: CooperationSelectMaskDescription            # 默认邀请类型（勾玉/美食等）

**邀请历史**：使用位掩码（1/2/4/8）对应不同协作类型，记录每种类型上次邀请的时间。

### 2.4 配置验证器 (model_validator)

```python
@model_validator(mode='before')
@classmethod
def validator_all(cls, v: dict) -> Any:
    invite_info_count = v.get('find_jade_config', {}).get('invite_info_count', 1)
    sup_account_count = v.get('find_jade_config', {}).get('sup_account_count', 1)
    # 将扁平化的配置项（如 invite_info_list_1, invite_info_list_2）
    # 重组为列表结构
    validator_list('invite_info_list', v, InviteInfo, invite_info_count)
    validator_list('sup_account_list', v, AccountInfo, sup_account_count)
    return v
```

**设计目的**：配置文件中列表项以 `list_name_1`, `list_name_2` 等扁平键存储，验证器将其重组为列表。

## 4. 核心代码逐行解释

### 4.1 script_task.py

#### 4.1.1 `run()` 主流程 (第16-46行)

```python
def run(self):
    self.fade_conf = self.config.find_jade  # 获取配置

    # 遍历所有小号
    for accountInfo in self.fade_conf.sup_account_list:
        logger.info("start %s-%s", accountInfo.character, accountInfo.svr)

        # 判断是否需要登录
        if not self.is_need_login(accountInfo):
            logger.warning("%s Skipped last Login Time:%s", ...)
            continue

        # 切换到该小号
        suc = SwitchAccount(self.config, self.device, accountInfo).switchAccount()
        if not suc:
            logger.warning("switch to %s-%s Failed", ...)
            continue

        # 动态创建 WantedQuests 扩展实例
        wq = self.CreatObjectFromModule("WantedQuests", config=self.config, device=self.device)
        wq.fade_conf = self.fade_conf  # 注入找勾玉配置

        try:
            wq.run()                   # 执行悬赏封印任务
        except TaskEnd as e:
            logger.warning("%s-%s TaskEnd", ...)
            self.fade_conf.update_account_login_history(accountInfo)  # 更新登录时间
            self.save_config()         # 保存配置
            continue
        except RequestHumanTakeover as e:
            raise                      # 人工干预异常直接上抛
        except Exception as e:
            logger.error(e)
            self.next_run("FindJade", success=False)

    self.next_run("FindJade", success=True)
    raise TaskEnd("FindJade")
```

#### 4.1.2 `is_need_login()` 登录判断 (第50-64行)

```python
def is_need_login(self, item: AccountInfo):
    lastTime = item.last_complete_time  # 上次完成时间
    now = datetime.now()

    # 规则1：距上次登录超过13小时，需要登录
    if now - lastTime > timedelta(hours=13):
        return True

    # 规则2：上次在夜间(18:00-05:00)，现在在白天(05:00-18:00)，需要登录
    if (lastTime.hour >= 18 or lastTime.hour < 5) and (18 > now.hour >= 5):
        return True

    # 规则3：上次在白天(05:00-18:00)，现在在夜间(18:00+)，需要登录
    if (5 <= lastTime.hour < 18) and now.hour >= 18:
        return True

    return False
```

**日夜交替逻辑**：悬赏封印每天刷新两次（5:00和18:00），所以需要在日夜交替时重新登录。

#### 4.1.3 `CreatObjectFromModule()` 动态模块加载 (第66-83行)

```python
def CreatObjectFromModule(self, task_name: str, **kwargs):
    module_name = 'script_task'
    from pathlib import Path
    module_path = str(Path.cwd() / 'tasks' / task_name / (module_name + '.py'))

    # 动态加载模块
    spec = importlib.util.spec_from_file_location(module_name, module_path)
    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)

    # 创建扩展类：继承 WantedQuests.ScriptTask，混入 WantedQuestsEx 的方法
    WQEX = type("WQEX", (module.ScriptTask,), {
        "need_invite_vip": WantedQuestsEx.need_invite_vip,
        "get_invite_vip_name": WantedQuestsEx.get_invite_vip_name,
        "next_run": WantedQuestsEx.next_run,
        "invite_success_callback": WantedQuestsEx.invite_success_callback,
        "get_config": WantedQuestsEx.get_config
    })
    wq = WQEX(**kwargs)
    return wq
```

**关键设计**：使用 `type()` 动态创建类，将 `WantedQuestsEx` 中的5个方法注入到 `WantedQuests.ScriptTask` 的子类中。这实现了**猴子补丁 (Monkey Patch)** 模式，但更加优雅（通过继承而非直接修改）。

#### 4.1.4 `next_run()` 调度逻辑 (第88-99行)

```python
def next_run(self, task: str, finish=False, success=None, server=True, target=None):
    now = datetime.now()
    if success:
        if 5 <= now.hour < 18:                              # 白天成功 → 下次18:05
            self.set_next_run(task, target=now.replace(hour=18, minute=5))
        elif now.hour < 5:                                  # 凌晨成功 → 下次05:05
            self.set_next_run(task, target=now.replace(hour=5, minute=5))
        else:                                               # 夜间成功 → 次日18:05
            self.set_next_run(task, target=now.replace(hour=18, minute=5) + timedelta(days=1))
    else:
        self.set_next_run(task, target=now + timedelta(minutes=10))  # 失败 → 10分钟后重试
```

### 4.2 WantedQuestsEx.py — 扩展方法

```python
def need_invite_vip(self):
    return True  # 始终需要邀请VIP

def get_invite_vip_name(self, ctype: CooperationType):
    if not self.fade_conf:
        return ""
    return self.fade_conf.get_invite_name(ctype)  # 从配置获取对应类型的邀请人名称

def next_run(self):
    pass  # 空实现，不设置下次运行（由 FindJade 主任务控制）

def invite_success_callback(self, ctype: CooperationType, name: str):
    if not self.fade_conf:
        return
    self.fade_conf.update_invite_history(ctype, name)  # 更新邀请历史
    self.config.save()                                   # 保存配置

def get_config(self):
    config = WantedQuestsConfig()
    config.invite_friend_name = "default"
    config.cooperation_only = True                        # 仅执行协作任务
    config.cooperation_type = self.fade_conf.get_cooperation_type_mask()  # 综合邀请类型掩码
    return config
```

### 4.3 config.py — 核心方法

#### 4.3.1 `InviteInfo.need_invite()` 邀请判断 (第34-46行)

```python
def need_invite(self, ctype: CooperationType):
    # 检查该协作类型是否在配置的邀请类型掩码中
    if not ctype & CooperationSelectMask[self.default_invite_type.value]:
        return False
    # 获取该类型的上次邀请时间
    last_time = self.__getattribute__("invite_history_" + str(ctype))
    now = datetime.now()
    # 与 is_need_login 相同的日夜交替逻辑
    if now - last_time > timedelta(hours=13):
        return True
    if (lastTime.hour >= 18 or lastTime.hour < 5) and (18 > now.hour >= 5):
        return True
    if (5 <= lastTime.hour < 18) and now.hour >= 18:
        return True
    return False
```

#### 4.3.2 `FindJade.get_cooperation_type_mask()` 类型掩码计算 (第93-102行)

```python
def get_cooperation_type_mask(self) -> CooperationSelectMaskDescription:
    result = CooperationSelectMask.NoInvite
    for info in self.invite_info_list:
        result |= CooperationSelectMask[info.default_invite_type]  # 按位或合并
    name = CooperationSelectMask(result).name
    return CooperationSelectMaskDescription(name)
```

**位掩码合并**：将所有邀请人的默认邀请类型通过按位或合并，得到一个综合掩码，用于过滤悬赏封印任务。

## 6. 设计模式总结

### 6.1 动态模块加载 + 猴子补丁

`CreatObjectFromModule()` 使用 `importlib` 动态加载模块，再用 `type()` 创建扩展子类注入方法。这比直接猴子补丁更安全（不修改原类），比装饰器更灵活（运行时决定）。

### 6.2 位掩码 (Bitmask) 模式

协作类型使用位掩码（1/2/4/8）表示，通过按位或 (`|`) 合并多种类型，通过按位与 (`&`) 检查是否包含某类型。这是经典的**标志位模式**。

### 6.3 扁平化序列化

配置中的列表以 `list_name_1`, `list_name_2` 扁平键存储，通过 `model_validator` 重组为列表，通过 `model_serializer` 展平回去。这是因为配置文件系统不支持嵌套列表。

### 6.4 时间窗口调度

`next_run()` 和 `is_need_login()` 都基于5:00/18:00两个时间窗口进行调度，体现了**定时任务调度器**的设计思想。

### 6.5 委托模式 (Delegation)

`FindJadeAssets` 为空类，所有UI操作委托给 `WantedQuests` 模块。`WantedQuestsEx` 中的方法在被调用时通过 `self.fade_conf` 访问找勾玉配置，实现了**控制反转**。

### 6.6 配置驱动的邀请管理

邀请人信息（名称、类型、历史）全部配置化，`need_invite()` 方法根据配置自动判断是否需要邀请，无需硬编码逻辑。
